# Vitosha Peak Explorer — release and investor readiness

This plan preserves the user's full objective: finish the frontend and backend, make the application ready to publish or present for acquisition/investment, and pursue a leading experience in its category. It is not a replacement objective or a declaration that a small MVP is sufficient.

## Direction and authority

- **Specified:** retain the recognizable Pirin panel skeleton, summit-only map labels, scroll zoom without Ctrl, and the glowing blue selected summit. Cesium ion aerial imagery and World Terrain remain the active renderer; the updated provider choice below supersedes the earlier fixed-provider preference.
- **Specified:** preserve stable bilingual place IDs, generated GeoJSON, local trail reports, and informational route previews.
- **Specified, updated goal:** prioritize the best available, attractive 3D relief over a fixed provider. Cesium ion and Mapbox are both authorized candidates; the supplied Mapbox public token may be used if needed. Raw data resolution, imagery, shading, framing and device performance must be evaluated separately; visual exaggeration is not new elevation detail.
- **Inferred:** the primary job is planning a hike to a Vitosha summit, comparing hut approaches, and understanding the terrain before leaving. Bulgarian and English visitors are both in scope.
- **Recommended, reversible implementation choice:** retain a static-first frontend; add a small Node production host for configuration, forecast caching, service health and security headers. This does not introduce accounts, personal tracking or shared reports.
- **Unresolved:** the commercial model, operator identity, production domain, provider commercial entitlements, branding rights and real customer validation. The business-model question has been sent to the user. Work independent of these answers continues.

## Execution sequence

1. Production foundation: pinned bundled dependencies, deployment host, configuration, weather service, data/schema tests, loading/recovery.
2. Complete planning journey: language switching, saved plans, sharing/export, elevation/provenance, calm map controls, mobile/keyboard navigation, local-report flow away from the removed top launcher.
3. Reliability and quality: persistent storage validation, offline facts, accessibility, performance, renderer regression checks, CI and release artifact verification.
4. Publication/investor package: deployment/runbook, licensing/operator checklist, privacy/attribution, competitive position, reproducible demo and evidence-backed dossier.
5. Final completion audit: every requirement, external entitlement, rendered journey and commercial claim verified; meaningful remaining work keeps the goal active.

Only one implementation slice is active at a time. Material changes to identity, payments, shared reporting, recurring costs or publication require the user's direction; routine reversible implementation work is already authorized.
